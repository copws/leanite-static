# Leanite Static 使用说明书

> 适用版本：Leanite 0.3.1
> 最后更新：2026-11-10

这份说明书面向「写博客的人」，不要求你熟悉 React 或 Vite。照着做，你就可以只用 Markdown 编辑器维护整个博客。

---

## 1. 这次改了什么

Leanite 原来是「浏览器 → LeanCloud → 页面」的动态博客。LeanCloud 停止服务后，这套结构无法继续工作，所以 0.3.0 把它改成了**静态博客**：

| 项目 | 旧版（0.2.x） | 新版（0.3.x） |
| --- | --- | --- |
| 文章存放 | LeanCloud 的 `BlogContent` / `BlogMeta` 表 | 项目里的 `content/posts/*.md` |
| 标签 | 单独维护 `Tags` 表 | 从文章 front matter 自动汇总 |
| 站点设置 | LeanCloud 的 `Settings` 表 | 项目根目录的 `blog.config.json` |
| 登录 | 管理员账号 + 密码（MD5 校验） | 前端密码门禁（SHA-256 校验，默认 admin/admin，可在设置修改） |
| 发布方式 | 网页里点“发布”，立即写入云端 | 导出 `.md` 放进项目，重新构建 |
| 阅读量 | 每次打开文章自动 +1 | 已移除：静态博客没有真实浏览统计，可接入第三方统计 |
| 页面网址 | `/article?id=xxx` | `/article/xxx/`、`/tag/标签/` |
| 部署 | 需要 LeanCloud 服务 | 纯静态文件，任意静态服务器 / GitHub Pages |
| 界面 | Leanite 原界面 | 保留原风格；顶部空白栏已移除，控制台入口放在右侧导航菜单 |

改造后没有任何云端依赖：不需要 LeanCloud 账号、AppID、AppKey，也不需要数据库。

### 1.1 它是怎么工作的

`npm run build` 时，项目里的 Vite 插件会：

1. 读取 `blog.config.json` 和 `content/posts/` 下的所有 Markdown；
2. 解析 front matter，检查日期、标签、重复网址等问题；
3. 把文章、标签、设置打包进前端代码；
4. 为首页、归档、每个标签、每篇文章、每个后台页面分别生成一个 `index.html`；
5. 生成 `sitemap.xml` 和 GitHub Pages 用的 `404.html`。

浏览器打开页面后，由 React 渲染出和原来一样的 Leanite 界面，Markdown 内容用 md-editor-rt 渲染。

> 说明：页面的正文仍然由浏览器渲染，但每个页面的标题、描述、canonical 已经在构建时写进 HTML，方便搜索引擎和分享卡片读取。这是为了在不改动原 UI 的前提下实现静态化。

## 2. 环境准备

- **Node.js**：需要 `^20.19.0` 或 `>=22.12.0`（Vite 7 的要求），推荐 Node 22 或 24。
- **npm**：随 Node 一起安装。
- 一个文本编辑器（VS Code、Typora、Obsidian 等都可以）。

检查版本：

```bash
node -v
npm -v
```

> **Windows PowerShell 提示**：如果执行 npm 时报“无法加载文件 npm.ps1，因为在此系统上禁止运行脚本”，可以把命令换成 `npm.cmd run build`、`npm.cmd run dev`，或者直接在 `cmd` 窗口里执行。

安装依赖（第一次使用、或者 `node_modules` 被删掉时）：

```bash
npm install
```

## 3. 目录结构

```text
leanite/
├─ blog.config.json          # 站点设置（名称、简介、头像、公告、部署路径……）
├─ content/
│  └─ posts/                 # 你写的所有文章
│     ├─ 2024-05-01-hello-world.md
│     ├─ 2024-06-15-markdown-guide.md
│     └─ 2026-11-10-from-leancloud-to-static.md
├─ public/                   # 原样复制到网站根目录的静态文件
│  ├─ .nojekyll              # GitHub Pages 用，避免 Jekyll 处理
│  ├─ 27_16_34_19_bxs-pyramid.png
│  └─ images/                # 建议把文章图片放在这里
├─ plugin/
│  └─ blog-content.ts        # 读取 Markdown、生成页面的构建插件
├─ scripts/
│  └─ import-leancloud.mjs   # 旧 LeanCloud 数据迁移脚本
├─ src/                      # React 界面代码（一般不需要改）
├─ docs/
│  └─ 使用说明书.md          # 本文件
├─ index.html
├─ vite.config.ts
└─ package.json
```

构建产物在 `dist/`，这个目录不需要提交到 Git（已在 `.gitignore` 里）。

## 4. 三分钟跑起来

```bash
# 1. 安装依赖（第一次）
npm install

# 2. 本地预览
npm run dev
```

终端会打印类似：

```text
➜  Local:   http://localhost:5173/leanite-static/
```

打开这个地址即可。注意地址后面有 `/leanite-static/`，这是因为 `blog.config.json` 里的 `base` 是 `/leanite-static/`，和 GitHub Pages 的仓库路径一致。

改文章或改设置后，开发服务器会自动刷新。

确认没问题后构建：

```bash
npm run build
```

构建完成后可以本地预览产物：

```bash
npm run preview
```

## 5. 写文章

### 5.1 新建文件

在 `content/posts/` 下新建一个 `.md` 文件，文件名建议写成：

```text
日期-英文短名.md
```

例如：

```text
2024-06-15-markdown-guide.md
```

Leanite 会**去掉文件名开头的 `YYYY-MM-DD-`**，把剩下的部分作为文章网址：

```text
content/posts/2024-06-15-markdown-guide.md
        ↓
https://你的站点/article/markdown-guide/
```

其他规则：

- 文件名也可以是中文，例如 `2024-06-15-我的生活.md`，网址会是 `/article/我的生活/`（浏览器里显示为百分号编码）。
- 以下划线 `_` 或点 `.` 开头的文件会被忽略，可以用来放模板，例如 `_template.md`。
- 大小写、空格会被统一处理：空格和下划线变成 `-`，英文转小写，网址里不允许的字符会被去掉。
- 两篇文章不能生成相同的网址；如果重复，构建会报错并告诉你冲突的文件。
- 想固定网址、不跟着文件名变，可以在 front matter 里写 `slug`，见下一节。

### 5.2 Front matter

文件开头用两行 `---` 包住的部分叫 front matter，用来写元数据：

```markdown
---
title: "文章标题"
date: 2024-06-15
tags:
  - "教程"
  - "Markdown"
draft: false
---

正文从这里开始。
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | 字符串 | 否 | 文章标题。不写时依次使用正文第一个一级标题、文件名。建议写。 |
| `date` | `YYYY-MM-DD` | 否 | 发布日期。不写时依次使用文件名里的日期、文件修改时间。**建议明确写**，否则换电脑后日期可能变化。 |
| `tags` | 数组 | 否 | 标签。支持 `tags: [教程, Markdown]` 或每行一个的写法。 |
| `draft` | 布尔 | 否 | `true` 表示草稿：不生成文章页面，不出现在首页/归档/标签/sitemap。默认 `false`。 |
| `description` | 字符串 | 否 | 页面描述，用于搜索结果和分享卡片。不写时自动截取正文。 |
| `slug` | 字符串 | 否 | 手动指定文章网址，优先于文件名。例如 `slug: about` 会生成 `/article/about/`。 |

字符串里如果有冒号、`#`、引号等字符，建议用英文双引号包起来，例如 `title: "从 LeanCloud 到静态博客：0.3.1"`。

### 5.3 标签

标签不用单独创建，Leanite 会把所有已发布文章的 `tags` 汇总成标签页。

- 标签页：`/tag/标签名/`
- 标签总览：`/tag/`
- 前端页面按文章数量从多到少排序

标签名会变成网址和文件夹名，因此不能包含这些字符：

```text
\ / : * ? " < > | # %
```

标签也不能以点开头，不能以点或空格结尾，不能使用 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`…）。违反规则时构建会报错并指出是哪篇文章。

### 5.4 草稿

把 `draft` 设为 `true`，这篇文章就不会出现在构建产物里：

```yaml
draft: true
```

行为说明：

- 不生成 `/article/.../` 页面；
- 不出现在首页、归档、标签、sitemap；
- **正文不会被打包进前端代码**，但标题、日期、标签、文件名仍会出现在后台的「文章管理」列表里（方便你知道还有哪些没写完）。

写好以后把 `draft` 改成 `false`，重新构建即可发布。

### 5.5 图片

推荐把图片放在 `public/images/` 下，例如 `public/images/cover.png`，然后在 Markdown 里写：

```markdown
![封面](/images/cover.png)
```

Leanite 会自动把以 `/` 开头的图片地址补上部署子路径。即使网站部署在 `example.com/blog/`，最终也会正确指向 `/blog/images/cover.png`，不需要手写 `/blog/`。

也支持完整网址：

```markdown
![封面](https://example.com/images/cover.png)
```

> 旧版 LeanCloud 文件域名（`lc-xxx.lcfile.com`）可能已经不可用。如果旧文章里的图片打不开，需要找到原图或备份，放进 `public/images/` 并修改链接。

### 5.6 站内链接

文章和标签的网址格式：

```text
/article/文章id/
/tag/标签名/
```

可以直接在 Markdown 里写：

```markdown
[另一篇文章](/article/hello-world/)
[看看教程标签](/tag/教程/)
```

以 `/` 开头的站内链接会自动补上部署子路径。外部链接照常写完整网址。

### 5.7 首页、归档和排序

- **首页**：按日期从新到旧，展示最新 **5 篇**已发布文章的**完整正文**（这是原版 Leanite 的设计）。
- **归档**：所有已发布文章按年份分组。
- **标签**：按标签分组。

如果想调整首页显示数量，可以修改 `src/pages/Home.tsx` 里的 `publishedPosts.slice(0, 5)`；不过这属于改代码，不是必需操作。

### 5.8 支持的 Markdown 语法

Leanite 使用 [md-editor-rt](https://github.com/imzbf/md-editor-rt) 渲染，支持：

- 标题、列表、引用、表格、代码块、链接、图片
- 任务列表、脚注、上下标
- 数学公式（KaTeX）
- Mermaid 图表
- 代码高亮

> 代码高亮和 KaTeX 的运行时资源由 md-editor-rt 从 CDN（unpkg）加载。完全离线或 CDN 被屏蔽时，正文仍能显示，但代码高亮/公式可能不生效。

### 5.9 常见格式错误

构建时如果 front matter 有问题，会直接失败并提示文件名和行号，例如：

```text
[Leanite] 2024-06-15-demo.md 的 front matter 有误：第 4 行：缺少冒号，格式应为 “key: value”
```

常见原因：

- `---` 只写了开头没写结尾；
- 字段行忘了冒号；
- 数组写成 `tags: [a, b`（少了 `]`）；
- 日期写成 `2024/06/15` 或 `6 月 15 日`（请用 `2024-06-15`）；
- 两篇文章的网址相同；
- 标签里有不允许的字符。

## 6. 写作台（后台）

点击右侧导航菜单里的「控制台」，或直接访问：

```text
/leanite-static/adminHome/
/leanite-static/modifyArticle/
```

访问控制台会先进入登录页。默认用户名和密码均为 `admin`，登录后才能进入；进入后右侧栏会显示「退出登录」入口。

> 这是前端密码门禁，只能挡住随手点进来的访客，不能真正保护源码里的内容。详见 6.5。

### 6.1 创建新文章

1. 登录控制台（默认账号密码均为 `admin`）；
2. 进入「文章管理」；
3. 点「创建新文章」；
4. 填写标题、日期、标签、描述、状态（发布/草稿）；
5. 在编辑器里写正文，右侧可以预览；
6. 点「导出 Markdown」，浏览器会下载一个 `.md` 文件；
7. 把下载的文件放进项目的 `content/posts/`；
8. 运行 `npm run dev` 预览，或 `npm run build` 发布。

### 6.2 本地草稿

编辑过程中可以点「保存本地草稿」。草稿保存在当前浏览器的 localStorage 里，键名是：

```text
leanite:drafts:v1
```

注意：

- 草稿只存在这台电脑的这个浏览器里，换浏览器/换电脑/清除站点数据都会丢失；
- 重要内容请及时「导出 Markdown」，放进项目并提交到 Git；
- 「本地草稿」区域可以继续编辑、导出或删除。

### 6.3 导入 Markdown

在「文章管理」页点「导入 Markdown」，选择一个 `.md` 文件，会把它读成一篇本地草稿。适合：

- 从别的博客系统迁移过来的文章；
- 在 Typora/Obsidian 里写好、想再检查一遍的文章。

如果文件本身带 front matter，会读取其中的标题、日期、标签、草稿状态；没有的话会尝试用第一个一级标题作为标题。

### 6.4 编辑已有文章

在「文章总览」里点「编辑」，会把构建时读到的正文载入写作台。你可以修改后重新导出。

- 导出时会沿用原来的文件名，避免网址变化；
- 如果原文章是草稿文件（`draft: true`），正文没有被打包进页面，写作台无法载入，只能直接在本地编辑该文件；
- 「复制源码」可以把完整 Markdown（含 front matter）复制到剪贴板。

### 6.5 关于安全性

控制台有一个前端密码门禁：默认用户名和密码均为 `admin`，可以在「设置 → 管理员账号」里修改。未登录时访问控制台地址会跳转到登录页；登录状态保存在当前标签页的 `sessionStorage` 里，关闭标签页后需要重新登录。

但它只是「做做样子」：

- 静态站点没有服务器，校验完全在浏览器里进行；
- 任何查看源码、修改 `sessionStorage` 或直接调用页面函数的人都能绕过；
- 密码以 SHA-256 哈希保存，不保存明文，但哈希同样在公开的 JS 里，仍然不能当作真实的安全措施。

因此：

- 不要在文章或配置里放真正的密码、密钥等敏感信息；
- 写作台的草稿只存在你自己的浏览器里，不会上传；
- 如果希望彻底不发布后台，最稳妥的做法是删掉后台相关代码和路由，而不是只删构建目录。

## 7. 标签管理

「标签管理」是只读的汇总视图，可以查看每个标签下有哪些文章。

标签不能在这个页面里新增、重命名或删除，因为它们完全由文章 front matter 决定。要修改标签：

1. 打开对应的 `content/posts/*.md`；
2. 修改 `tags`；
3. 重新构建。

## 8. 站点设置

站点设置保存在项目根目录的 `blog.config.json`，**构建时读取**。有两种修改方式。

### 8.1 直接编辑文件（推荐）

```json
{
  "title": "Leanite 开发日志",
  "name": "Leanite 开发日志",
  "desc": "记录 Leanite 的成长，也记录我的生活。",
  "avatarURL": "/27_16_34_19_bxs-pyramid.png",
  "blogIcon": "/27_16_34_19_bxs-pyramid.png",
  "bulletin": "欢迎来到 Leanite 静态版！\n\n在 content/posts 里写文章，运行 npm run build 即可。",
  "siteURL": "https://copws.github.io/leanite-static/",
  "base": "/leanite-static/",
  "version": "0.3.1",
  "language": "zh-CN",
  "adminUsername": "admin",
  "adminPasswordHash": "8c6976e5b5410415bde908bd4dee15dfb167a9c873fc4bb8a81f6f2ab448a918"
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `title` | 浏览器标签页标题，也是首页标题 |
| `name` | 站点名称，用于页面标题后缀（`文章标题 - 站点名`）和侧栏资料卡 |
| `desc` | 一句话简介，显示在侧栏资料卡，也是首页的 description |
| `avatarURL` | 侧栏头像。支持 `/images/avatar.png` 这样的站内路径，或完整 URL |
| `blogIcon` | 浏览器标签页图标。支持站内路径或完整 URL，页面加载后会应用 |
| `bulletin` | 侧栏公告，支持 Markdown，用 `\n` 换行 |
| `siteURL` | 站点完整地址，用于 canonical、分享卡片和 sitemap；留空则不生成这些 |
| `base` | 部署子路径。域名根目录填 `/`；GitHub Pages 仓库页填 `/仓库名/` |
| `version` | 页脚显示的版本号 |
| `language` | 写入 `<html lang>`，默认 `zh-CN` |
| `adminUsername` | 控制台登录用户名，默认 `admin` |
| `adminPasswordHash` | 控制台密码的 SHA-256 哈希，默认是 `admin` 的哈希；不要填明文密码 |

> 默认的 `adminPasswordHash` 是 `8c6976e5b5410415bde908bd4dee15dfb167a9c873fc4bb8a81f6f2ab448a918`（即 `admin`）。要手写新密码的哈希，可以运行：
>
> ```bash
> node -e "console.log(require('crypto').createHash('sha256').update('新密码').digest('hex'))"
> ```
>
> 更推荐直接使用设置页生成，不需要手动算。

`base` 非常重要：

- 部署在 `https://用户名.github.io/仓库名/` → `"/仓库名/"`
- 部署在 `https://用户名.github.io/` → `"/"`
- 部署在自己的域名根目录 → `"/"`
- 部署在 `https://example.com/blog/` → `"/blog/"`

必须以 `/` 开头、以 `/` 结尾。写错会导致白屏、资源 404 或路由错乱。

### 8.2 用设置页生成

「设置」页可以可视化地修改这些字段，然后：

- 点「生成配置文件」下载 `blog.config.json`；
- 或点「复制配置」把 JSON 复制到剪贴板。

用它替换项目根目录的同名文件，然后重新构建。设置页不会直接修改项目文件（浏览器没有这个权限），也不会在线生效。

> 修改 `base` 后，开发服务器需要重启（`Ctrl+C` 后重新 `npm run dev`），因为 Vite 的资源前缀是在启动时确定的。

### 8.3 网站图标（favicon）

浏览器标签页图标默认由 `index.html` 里的这一行决定：

```html
<link rel="icon" href="/27_16_34_19_bxs-pyramid.png" />
```

这是首屏的默认图标。页面加载后，Leanite 会用构建时读到的 `blog.config.json` 里的 `blogIcon` 覆盖它。修改 `blogIcon` 后需要重新构建才会生效；如果想连首屏默认值一起改，替换 `public/` 里的图片或修改上面这一行。

## 9. 构建与部署

### 9.1 构建

```bash
npm run build
```

产物在 `dist/`：

```text
dist/
├─ index.html                    # 首页（也作为根路径入口）
├─ 404.html                      # 未知路径的兜底页面
├─ sitemap.xml                   # 站点地图（需要 siteURL）
├─ .nojekyll                     # GitHub Pages 用
├─ home/index.html
├─ tag/index.html
├─ tag/标签名/index.html
├─ article/index.html            # 归档
├─ article/文章id/index.html
├─ authentication/index.html     # 管理员登录
├─ adminHome/index.html
├─ modifyArticle/index.html
├─ modifyTags/index.html
├─ settings/index.html
└─ static/                       # JS、CSS、图标
```

每个页面都有独立的 HTML 文件和自己的 `<title>`、description、canonical、Open Graph 标签。直接访问、刷新、分享深链接都能正常打开。

### 9.2 本地预览产物

```bash
npm run preview
```

打开终端提示的地址（默认 `http://localhost:4173/leanite-static/`）。预览的是真正的 `dist/`，和线上一致。

### 9.3 部署到 GitHub Pages

**方法一：GitHub Actions（推荐）**

在仓库里添加 `.github/workflows/deploy.yml`：

```yaml
name: Deploy Leanite

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

然后到仓库的 **Settings → Pages**，把 Source 设为 **GitHub Actions**。

**方法二：手动上传 `dist/`**

把 `dist/` 里的全部文件上传到 GitHub Pages 对应的分支（通常是 `gh-pages`），或上传到任何静态服务器。

部署前确认：

- `blog.config.json` 的 `base` 和仓库路径一致（本项目是 `/leanite-static/`）；
- `siteURL` 填的是最终访问地址；
- 仓库里不要提交 `dist/`（已在 `.gitignore`）。

### 9.4 部署到其它地方

- **Netlify / Cloudflare Pages / Vercel**：构建命令 `npm run build`，输出目录 `dist`。`base` 按实际路径填，通常部署在根目录时填 `/`。
- **Nginx**：把 `dist/` 放到站点目录，并配置：

  ```nginx
  location / {
      try_files $uri $uri/ $uri/index.html /404.html;
  }
  ```

- **Apache**：启用 `mod_rewrite`，或在 `.htaccess` 里把未知路径指向 `404.html`。

### 9.5 关于 404 和结尾斜杠

文章的规范地址带结尾斜杠：

```text
/leanite-static/article/hello-world/
```

Leanite 生成的页面也是这个结构。大多数静态服务器会自动处理不带斜杠的访问，GitHub Pages 会重定向到带斜杠的地址。如果遇到刷新 404，检查服务器是否配置了目录索引或 `404.html` 兜底。

`404.html` 会加载 Leanite 应用并把未知路径重定向回首页，所以自定义 404 页面不需要额外配置。

### 9.6 搜索收录

- `sitemap.xml` 会列出所有公开页面，可以在 Google Search Console / Bing Webmaster Tools 里提交；
- 后台页面带有 `noindex`，不会进 sitemap；
- 如果站点部署在子路径（如 `/leanite-static/`），`sitemap.xml` 也在子路径下，提交时用完整地址：`https://你的域名/leanite-static/sitemap.xml`。

## 10. 迁移旧 LeanCloud 文章

### 10.1 如果你导出过 LeanCloud 数据

LeanCloud 控制台的「数据存储 → 导出」会为每个 Class 生成 JSON Lines 文件，例如 `BlogContent.jsonl`、`BlogMeta.jsonl`。把导出的文件放进一个目录，然后执行：

```bash
# 先预览会生成哪些文件，不写入
npm run import:leancloud -- ./leancloud-export --dry-run

# 确认无误后正式生成到 content/posts/
npm run import:leancloud -- ./leancloud-export
```

也可以直接用 Node：

```bash
node scripts/import-leancloud.mjs ./leancloud-export
node scripts/import-leancloud.mjs ./leancloud-export --out ./content/posts
```

脚本会：

- 递归读取目录里的 `.json` / `.jsonl` / `.ndjson` 文件；
- 按文件名和字段判断哪些是 `BlogContent`、哪些是 `BlogMeta`；
- 用文章的 `id` 字段把正文和元数据合并；
- 用 `BlogMeta.createdAt` 作为发布日期；
- 用 `BlogMeta.tags` 作为标签；
- 旧版的 `reader` 阅读量字段会被忽略（静态博客不做浏览统计）；
- 保留 `isDraft`，草稿会生成 `draft: true` 的文件；
- 输出文件名格式为 `日期-标题.md`，标题里的非法字符会被清理。

生成后建议：

1. 打开几篇文章检查正文、标签、日期；
2. 删除或修改不想公开的草稿；
3. 运行 `npm run dev` 检查排版和图片；
4. 运行 `npm run build` 构建。

> **旧链接说明**：旧版文章网址是 `/article?id=一串id`，新版按文件名生成 `/article/文章id/`，所以旧的分享链接不会自动对应到新文章。如果某篇文章的旧链接很重要，可以在它的 front matter 里用 `slug` 指定一个固定的网址，然后把新地址通知给读者。

### 10.2 如果没有导出数据

只能从旧的网页缓存、搜索引擎快照、自己的备份或 LeanCloud 后台残留数据里手动复制正文，然后按第 5 节新建 Markdown 文件。

### 10.3 旧图片

LeanCloud 的文件存储域名可能已经无法访问。需要：

1. 找到原图（本地备份、浏览器缓存、LeanCloud 文件备份）；
2. 放进 `public/images/`；
3. 把文章里的图片地址改成 `/images/文件名`。

### 10.4 旧站点设置

把旧版 `Settings` 表里的 `name`、`desc`、`avatarURL`、`blogIcon`、`bulletin` 复制到 `blog.config.json` 对应字段即可。旧的管理员账号密码不必迁移，新版默认是 `admin` / `admin`，可在「设置 → 管理员账号」里改成新的。

## 11. 常见问题

### 页面一片空白，控制台报资源 404

`blog.config.json` 的 `base` 和实际部署路径不一致。比如部署在 `https://xxx.github.io/leanite-static/`，`base` 必须是 `/leanite-static/`；部署在域名根目录则必须是 `/`。修改后重新构建。

### 直接访问文章地址或刷新时 404

- 确认地址带结尾斜杠：`/article/hello-world/`；
- 确认服务器把未知路径交给 `404.html` 或 `index.html`；
- GitHub Pages 会自动使用生成的 `404.html`，其它服务器需要按 9.4 配置。

### 新写的文章没有出现

检查：

1. 文件是否在 `content/posts/` 下；
2. 文件名是否以 `_` 或 `.` 开头（会被忽略）；
3. `draft` 是否为 `true`；
4. 是否重新运行了 `npm run dev` / `npm run build`；
5. 构建日志里是否有该文章的警告或错误。

### 修改标题后网址变了

网址来自文件名（去掉日期前缀）。如果想保持旧网址：

- 不改文件名；或
- 在 front matter 里加 `slug: 原来的网址`。

### 为什么页面上没有阅读量了

静态博客没有后端，无法记录真实的浏览数，所以 0.3.0 直接移除了阅读量显示。如果以后需要统计，可以接入第三方分析工具（如 Umami、Google Analytics、Cloudflare Web Analytics）。旧 front matter 里的 `views` 字段会被忽略，不会报错。

### 后台页面会被别人看到吗

控制台地址本身是可以访问的，但未登录会被跳转到登录页。默认账号密码均为 `admin`，请尽快在「设置 → 管理员账号」里改掉。要注意这只是前端门禁，查看源码或修改浏览器存储的人仍然可以绕过，不要在里面放真正的秘密。详见 6.5。

### 忘记管理员密码了怎么办

控制台的密码哈希可能在两个地方：

1. `blog.config.json` 的 `adminPasswordHash`（构建时写入站点）；
2. 当前浏览器的 localStorage 键 `leanite:admin-credentials:v1`（设置页「保存账号到本浏览器」写入）。

处理办法：

- 先在浏览器开发者工具的 Application → Local Storage 里删除 `leanite:admin-credentials:v1`，再删除 sessionStorage 里的 `leanite:authed`，然后使用配置里的账号登录；
- 如果配置里的密码也忘了，把 `adminUsername` 改回 `admin`，`adminPasswordHash` 改成默认值 `8c6976e5b5410415bde908bd4dee15dfb167a9c873fc4bb8a81f6f2ab448a918`，重新构建，就可以用 `admin` / `admin` 登录；
- 登录后立刻在设置页改一个新密码。

### 登录时提示“当前环境不支持密码校验”

密码校验使用浏览器的 Web Crypto（SHA-256），它只在安全上下文中可用。请用 `https://` 或 `http://localhost` 访问站点，不要用局域网 IP 的普通 `http://` 地址登录。

### 本地草稿丢了

草稿存在浏览器的 localStorage 里，清除站点数据、换浏览器、隐私模式都会丢失。养成及时「导出 Markdown」并提交 Git 的习惯。

### 构建时报 front matter 错误

按提示的行号检查 `---`、冒号、数组括号和日期格式。字段名只能使用字母、数字、下划线和短横线。

### 构建时报标签错误

标签里不能有 `\ / : * ? " < > | # %`，不能以点或空格结尾，不能是 Windows 保留名。换一个标签名即可。

### 开发服务器突然退出

如果终端出现 `EBUSY: resource busy or locked, watch ...`，通常是编辑器保存时产生的临时文件被文件监听器占用。项目已经在 `vite.config.ts` 里忽略 `*.tmp` 和 `*.tmpdir`；如果仍然出现，重新运行 `npm run dev` 即可，不会影响构建产物。

### 能不能不用写作台，直接在编辑器里写

可以，而且推荐。写作台只是可选的辅助工具；你完全可以直接在 VS Code / Typora / Obsidian 里编辑 `content/posts/*.md`，然后运行构建。

## 14. 最后

Leanite 的界面风格尽量保持了原样（顶部空白栏已移除，控制台入口移到了右侧导航菜单），变的是内容的来源和发布方式。只要记住一句话：

> **文章是 `content/posts/` 里的 Markdown，站点是 `blog.config.json`，发布就是 `npm run build`。**

遇到问题先看构建日志，日志里的文件名和行号通常能直接定位原因。
