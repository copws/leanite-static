欢迎来到 Leanite Static！

这篇文章整理了在 Leanite Static 里写文章需要知道的约定。掌握这些，你就可以完全离开后台，只用编辑器和 Git 来维护博客了。

## 文件放在哪里

所有文章都放在 `content/posts/` 目录下，一个文件对应一篇文章。文件名建议使用：

```
日期-英文短名.md
```

例如 `2024-06-15-markdown-guide.md`。Leanite 会去掉文件名开头的 `YYYY-MM-DD-`，把剩下的部分作为文章的网址，也就是 `/article/markdown-guide/`。中文文件名也可以正常工作，但英文短名更利于分享。

以下划线 `_` 或点 `.` 开头的文件会被忽略，可以用来放草稿模板。

## Front matter

每个文件开头用两行 `---` 包起来的部分叫 front matter，用来写文章的元数据：

```yaml
---
title: "文章标题"
date: 2024-06-15
tags:
  - "教程"
  - "Markdown"
draft: false
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 否 | 文章标题；不写时使用正文第一个一级标题或文件名 |
| `date` | 否 | 发布日期，格式 `YYYY-MM-DD`；不写时依次尝试文件名日期、文件修改时间 |
| `tags` | 否 | 标签数组，也可以写成 `tags: [教程, Markdown]` |
| `draft` | 否 | 设为 `true` 时文章不会出现在网站上 |
| `description` | 否 | 页面描述，用于搜索结果和分享卡片；不写时自动截取正文 |
| `slug` | 否 | 手动指定文章网址，优先于文件名 |

## 标签

标签不需要单独创建，Leanite 会自动把所有文章的 `tags` 汇总成标签页。修改文章的标签后重新构建，标签页和标签列表会一起更新。

标签里不能包含 `\ / : * ? " < > | # %` 这些字符，因为它们会变成网址和文件夹名。

## 草稿

把 `draft` 设为 `true`，这篇文章就不会被打包进网站。也可以直接在写作台里把文章标成草稿。

草稿的正文不会出现在构建产物里，但草稿的标题会出现在后台的「文章管理」列表中，方便你知道还有哪些没写完。

## 图片和站内链接

把图片放进 `public/images/`，然后在 Markdown 里写：

```markdown
![图片说明](/images/example.png)
```

构建时 Leanite 会自动为以 `/` 开头的图片和链接补上部署子路径，所以即使网站部署在 `example.com/blog/` 这样的子目录下也能正常显示。

## 支持的 Markdown 语法

除了标准的标题、列表、引用、表格、代码块之外，md-editor-rt 还原生支持：

- 任务列表
- 脚注
- 上下标
- 数学公式（KaTeX）
- Mermaid 图表
- 代码高亮

```js
const hello = (name) => `Hello, ${name}!`;
console.log(hello("Leanite"));
```

> 写作时不用太在意排版，Leanite 的预览主题会处理好细节。

## 让网址保持稳定

文章的网址来自文件名。如果你改了标题，但想保留原来的网址，可以：

1. 不修改文件名；或者
2. 在 front matter 里加一行 `slug: 原来的网址`。

已经发布出去的文章最好不要随意改文件名，否则旧的分享链接会失效。
